3. # Public Holidays

Финальный проект по Android-разработке.

Приложение показывает государственные праздники из открытого API и расширяет базовый проект до персонализированного offline-first mini-product с локальными профилями, историей, избранным, заметками, настройками, кэшем и фоновой синхронизацией.

## Что было добавлено в финальной работе

По сравнению с исходным проектом были добавлены:

- экран настроек;
- экран истории просмотров;
- локальные профили пользователей;
- создание, выбор и удаление профиля;
- раздельные пользовательские данные для разных профилей;
- избранные праздники;
- единые личные заметки к праздникам;
- локальный кэш праздников;
- TTL-политика кэша;
- offline-first загрузка данных;
- фоновая синхронизация через WorkManager;
- тёмная тема через DataStore;
- тесты на новую функциональность.

## Новые пользовательские данные

В проекте появились следующие локальные пользовательские данные:

- профили пользователей;
- активный выбранный профиль;
- история просмотренных праздников;
- избранные праздники;
- личные заметки к праздникам;
- кэш праздников из API;
- настройка тёмной темы.

## Где хранятся данные

### Room

Room используется для данных приложения и пользовательских сущностей:

- `UserEntity` — локальные профили пользователей;
- `FavoriteHolidayEntity` — избранные праздники пользователя;
- `HolidayHistoryEntity` — история просмотров;
- `HolidayNoteEntity` — личные заметки к праздникам;
- `CachedHolidayEntity` — локальный кэш праздников из API.

Пользовательские данные разделены по `userId`.

### DataStore

DataStore используется только для настроек и предпочтений приложения:

- активный пользователь;
- состояние тёмной темы.

Пользовательские сущности уровня истории, заметок, избранного и кэша не хранятся в DataStore.

## Новые пользовательские сценарии

### 1. Управление профилями

Пользователь может создать локальный профиль, выбрать активный профиль и удалить ненужный профиль.

Для каждого профиля отдельно хранятся:

- история просмотров;
- избранное;
- заметки;
- страна по умолчанию.

При удалении профиля удаляются связанные с ним пользовательские данные: история, избранное и заметки.

### 2. История просмотров

Когда пользователь открывает экран деталки праздника, праздник добавляется в историю текущего профиля.

История:

- хранится в Room;
- разделена по пользователям;
- сортируется по последнему просмотру;
- не создаёт дубликаты одного и того же праздника;
- ограничена по размеру.

### 3. Избранные праздники

Пользователь может добавить праздник в избранное и удалить его оттуда.

Избранное:

- хранится в Room;
- разделено по пользователям;
- связано с конкретным праздником через `holidayId`;
- отображается отдельным пользовательским разделом.

### 4. Личные заметки к праздникам

Пользователь может написать заметку к празднику.

Заметка единая: она отображается и редактируется как на экране деталки, так и в избранном.

Заметки:

- хранятся в Room;
- разделены по пользователям;
- привязаны к конкретному празднику;
- имеют составной ключ `userId + holidayDate + countryCode`;
- удаляются, если пользователь очищает текст заметки.

## Offline-first логика

Приложение построено по принципу offline-first.

Праздники загружаются из API и сохраняются в локальный кэш Room.

При повторной загрузке приложение сначала проверяет локальные данные:

- если кэш есть и он свежий, данные берутся из Room;
- если кэш устарел, приложение пытается обновить данные из сети;
- если сеть недоступна, но локальный кэш уже есть, приложение показывает сохранённые данные;
- если локальных данных нет и сеть недоступна, показывается ошибка.

Так UI не зависит полностью от сети, а локальные данные реально используются приложением.

## Политика актуальности данных

Для кэша используется TTL.

Свежим считается кэш, обновлённый не позднее 7 дней назад.

Слишком старый кэш может очищаться фоновой задачей.

## WorkManager

WorkManager используется для обслуживания offline-first логики.

Фоновая задача `HolidaySyncWorker`:

- удаляет слишком старый кэш;
- определяет страну активного пользователя;
- обновляет праздники для текущего года;
- предзагружает праздники на следующий год;
- сохраняет полученные данные в Room.


## Тесты

### `HolidaysRepositoryRoomTest`

Проверяет бизнес-логику, Room и offline-first:

- возврат локального кэша при ошибке сети;
- добавление и удаление избранного;
- разделение данных по пользователям;
- сохранение заметки только для выбранного пользователя;
- удаление заметки при пустом тексте;
- добавление истории без дублей.

### `HolidaysNavigationTest`

Проверяет экранную и навигационную логику:

- открытие деталки из списка;
- передачу полного `holidayId`;
- отображение правильного праздника.

### `HolidaySyncWorkerTest`

Проверяет background / sync часть:

- запуск `HolidaySyncWorker`;
- загрузку данных через API;
- кэширование текущего года;
- предзагрузку следующего года;
- сохранение результата в Room.

## Как проверить работу

1. Запустить приложение.
2. Создать новый профиль.
3. Переключиться между профилями.
4. Загрузить список праздников.
5. Открыть деталку праздника.
6. Добавить заметку.
7. Добавить праздник в избранное.
8. Проверить, что заметка видна и в деталке, и в избранном.
9. Открыть историю просмотров.
10. Выключить сеть и проверить, что ранее загруженные праздники доступны из кэша.
11. Включить тёмную тему в настройках.
12. Удалить профиль и проверить, что связанные данные удаляются.
